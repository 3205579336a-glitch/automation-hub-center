## 1. 系统简介

Purchasing Automation Hub 是本地优先的 Windows 桌面软件，用于减少重复采购操作并支持批量处理 SAP 数据。你提供已保存的 Excel 文件；系统检查文件、展示预览，再通过你已有的授权 SAP 访问处理符合条件的记录。

四个功能分别用于创建采购单据、更新采购数据或查询日期，影响并不相同。APQP 只读取 SAP，但会向 Excel 写入结果；RFQ、SLT、Source List 可以修改 SAP 业务数据。

执行历史和诊断信息保存在本机。SAP 通信仍通过公司系统与网络进行。软件不会替代业务审批，不会自动维护缺失主数据，也不保证固定完成时间。

## 3. 开始前检查

请逐项确认：

- 使用公司批准的 Windows 电脑及批准分发的 V0.2.4 软件包。
- 已连接公司网络或所需 VPN。
- 已安装 Microsoft Excel，输入文件和结果保存位置可写。
- 使用 RFQ、APQP、Source List 时，已安装 SAP GUI，且公司允许使用 SAP GUI Scripting。
- 使用 SLT 时，已安装设置中选定的 Google Chrome 或 Microsoft Edge。
- 具备相应 SAP 业务权限。SLT 需要 **ME12 采购信息记录修改权限**；没有权限时联系 Key User 或 IT。
- 明确本次 SAP 环境和 Plant，按提示在 SAP 或浏览器中自行登录。
- 已保存 Excel，并核对物料、供应商、数量和日期。
- 为自动化保留空闲 SAP 窗口，窗口中没有未保存的人工业务操作。

使用完整打包版本时，用户**无需安装 Python、pip 包、Node.js 或开发工具**。公司 SAP GUI、Excel、浏览器、网络及业务权限仍是必要条件。

> **警告 — 正式系统访问** — 普通 RFQ 页面面向 **VCE Production [949]，Client 100**。`[949]` 是 SAP Logon 连接条目标识，不是 Client。该页面没有 QA 切换。首次试用请由 Key User 安排授权的小批量验收，不要默认普通页面会进入测试系统。

## 4. 下载与解压软件

### 4.1 选择本机可写目录

下载 ZIP 后，将**完整软件包**解压到 C: 盘上的本机可写目录，例如：

`C:\Users\<YourUserName>\PurchasingAutomationHub\`

如果有写入权限，也可使用 `C:\PurchasingAutomationHub\`。在自己有权限的本机目录解压，不代表需要管理员权限。

避免网络盘、公司共享盘、受限目录、只读目录，以及 SharePoint／OneDrive 同步的运行目录。一个盘符并不能证明该目录是本机目录或可写。

### 4.2 解压并启动

1. 从批准的内部分发渠道或 Key User 获取 ZIP。
2. 右键 ZIP，选择 **Extract All／全部解压缩**。
3. 选择本机可写目录。
4. 等待解压完成，不要在文件仍复制时启动。
5. 打开解压后的目录。
6. 确认 `SAP Automation Toolbox.exe`、`resources`、`locales` 和其他配套文件仍在一起。
7. 双击 **SAP Automation Toolbox.exe**。

> **重要** — 不要直接在 ZIP 内运行 EXE；不要只复制 EXE 或移动单独 DLL／运行时文件。完整目录才是可运行软件。

更新时先停止所有任务并退出旧 Hub。将新版本完整解压到独立目录，不要混用不同版本的文件。历史和设置位于每个用户的本地数据目录，不是普通安装目录文件。不要为了排查启动故障而删除这些数据。

### 4.3 Windows 提示未知发布者时

便携版本未签名，Windows 可能显示 **Unknown Publisher／未知发布者**或安全警告。先与 Key User 确认来源，再按公司规定操作。如果终端安全软件阻止运行，请联系 IT；不要关闭杀毒软件、绕过公司限制或反复强行启动。

点击 Run 后无窗口时，查第16章启动类问题。另一台电脑能够启动，不代表当前终端的安全策略也允许运行。

## 5. 首次启动与 SAP 登录

1. 等待出现**仪表盘**。首次使用的统计为0属正常情况。
2. 查看左侧导航底部 **Version 0.2.4**。
3. 如需调整语言、主题、字体或声音，进入**设置**，修改后点**保存设置**。
4. 进入**操作中心**选择功能，不需要配置 Python 路径或 `.env` 文件。

SAP GUI 功能使用已登录且符合条件的空闲会话。SAP 未打开时，系统可能启动已安装的 SAP Logon；你仍需选择正确环境并完成登录。无法识别安全会话时，按登录提示处理，不要在 SAP 中随意点击。

SLT 会打开 WebGUI 浏览器窗口。Windows 可能要求选择客户端证书；选择自己的授权证书，并在**每个已打开的工作窗口**完成 SAP 登录。软件不会自动关闭证书选择框。完成提示的登录后，在 Hub 中使用当前可用的 Continue／重新检查按钮。

Hub 不要求输入或保存 SAP 密码。不要把密码填入模板、日志或支持消息。浏览器配置可能按浏览器和公司策略保留登录状态。

> **注意** — 如果 SAP 弹出重复登录警告，不要为了继续自动化就选择结束其他登录。先停止并联系 Key User 确认可用会话；结束其他登录可能丢失未保存工作。

## 6. 认识界面

### 6.1 仪表盘

仪表盘显示四个可用功能、今日运行、成功／失败运行、最近活动及预计节省时间。这些是**本机历史统计**，不是公司整体数据。新电脑或已清理历史时，数据会较少或为空。

预计节省时间以已确认成功的分组／记录及人工耗时基准计算，再扣除整批实际耗时，包括 SAP 等待和人工暂停。它是**估算**，不是实测的个人生产率。参考人工耗时为 RFQ 每组35分钟，SLT、APQP、Source List 每条5分钟；Source List 仍为参考假设，Key User 可以根据实测校准。

跳过、失败、取消或尚未核查的工作不计入成功数量。删除历史可能减少这些统计。

## 7. 标准操作流程与清空本页

**选择功能 → 下载模板 → 填写并保存 Excel → 上传 → 自动校验 → 核对预览 → 按需确认 → 执行 → 查看并另存结果。**

1. 在操作中心点所需任务的**打开**。
2. 点**下载模板**，在保存对话框选择位置。通知会显示实际保存路径，不一定是 Downloads。
3. 在对应输入工作表从第2行填写，保留必需表头和模板结构。
4. 先保存 Excel，再点**上传已填写模板**。
5. 等待校验。失败时查详情、修正并保存，然后重新上传。有符合条件的数据后才会启用开始按钮。
6. 核对数量、抽样、供应商、日期和业务选项；文件有效并不等于业务审批完成。
7. 写 SAP 的任务需要确认本批操作；APQP 只读 SAP，不要求采购写入确认。
8. 保持 SAP／浏览器窗口打开，让 Hub 操作，不要人工点击其正在控制的会话。
9. 查看成功、跳过和失败结果，打开文件，并把重要结果另存到批准的业务存储位置。

> **警告** — 运行中不要修改采购输入、排序数据行或重命名工作表。Excel 可以打开，但正在处理的数据必须保持稳定。

### 7.1 清空本页不是删除或回滚

选择**清空本页 → 确认清空**，会将本任务的文件选择、业务参数、预览、消息和结果展示恢复默认；其他任务页面不受影响。处理过程中不可清空。

此操作**不删除**上传文件、下载模板、执行历史和日志，也不会撤销 SAP 修改。想保留页面时点取消。引导式结果中的**运行另一任务**也会重置当前页。日志清理是另一种操作，见第14章。

## 8. 创建 Buyer Receipt 和 RFQ

### 8.1 用途与正式系统警告

打开**在 NPL 中自动批量创建 Buyer Receipt 和 RFQ**。系统查询指定 NPL 物料，创建 Buyer Receipt，确认已保存且状态为绿色，再继续创建 RFQ。

> **警告 — 正式系统操作** — 本功能在 VCE Production [949]、Client 100 创建真实采购单据。开始前核对工厂、项目、供应商、数量和日期。普通页面没有 QA 切换，也没有并发 RFQ 工作窗口选项。

![RFQ 模板准备](manual-assets/04-rfq-prepare.png)

*图4 - RFQ 准备区及下载、上传按钮。*

### 8.2 填写 RFQ 模板

使用 `Create_RFQ_Template.xlsx` 的 **RPA_Input**。每行代表指定工厂、项目、供应商的一颗物料。可选值为空时也不要删除表头。数量应为批准的数值，不要填单位或说明文字。

| 列 | 表头 | 填写要求 |
| --- | --- | --- |
| A | Plant | 必填。模板默认 C100，逐行确认。 |
| B | Project No. | 必填的正式项目编号，使用当前表头，不使用旧 MPP 名称。 |
| C | Material No. | 必填物料编号。 |
| D | Supplier Parma | 必填目标供应商代码。 |
| E | Supplier Email | 保留表头。RFQ／邮件流程需要时填写批准的邮箱；已填邮箱须有效。仅文件校验不会直接拒绝空值。 |
| F | Quotation Due Date | 必填。推荐 YYYY-MM-DD，如 2030-12-31，或真正的 Excel 日期。 |
| G | PPAP Date | Hub 模板中必填的批准日期。 |
| H | Technology | 必填 Buyer Receipt 所需的 Technology 用户／代码。 |
| I | 12 MR Qty | 必填批准的12个月数量，不自动补默认值。 |
| J | RFQ Qty Prototype | 选填。空白表示不向 SAP 写入这项数量，并不等于0。 |
| K | RFQ Qty Serial | 必填批准的量产数量，不自动补默认值。 |
| L | Cost Breakdown | Yes 保留 SAP 原复选框状态；No／空白强制取消已配置供应商的勾选。 |

> **重要 — Cost Breakdown** — Yes **不会**自动勾选原本未勾选的框。No／空白会强制取消已有勾选。每批都应核对这项业务选择。

日期优先使用明确的年-月-日格式。虽然系统能规范多种日期格式，也不应依赖易混淆的日／月顺序。新模板 I/J/K 刻意为空，请自行填写 I 和 K。

### 8.3 上传并核对

1. 保存完成的文件，再上传。
2. 核对物料数、RFQ 分组数、无效行、重复提示和警告。
3. 必填字段为空时修正对应 Excel 行并重新上传。
4. 展开 **View details · RPA_Input／查看明细**，检查输入和校验消息。
5. 核对每个 Parma 分组及其中全部物料。

![RFQ 校验错误](manual-assets/05-rfq-validation.png)

*图5 - 刻意缺少必填项的培训行，显示对应校验错误。*

分组规则是 **Plant + Project + Supplier Parma**，每组最多 **50颗物料**；超过上限会拆组。完全相同的输入重复行会跳过；同物料／分组存在不同业务输入时必须修正。工作簿已有成功状态的行也可能排除在新执行之外。

同组公共抬头数据沿用该组第一行的输入。如果邮箱、报价截止日期或其他公共值不同，预览会给出警告。开始前解决非预期差异；分组规则不代表会按每个不同日期自动创建独立 RFQ。

![有效 RFQ 预览](manual-assets/06-rfq-preview.png)

*图6 - 已校验物料及一个培训供应商分组。*

### 8.4 确认并执行

1. 在顶部点**开始自动化**。
2. 阅读 **Ready to Start／确认开始**，核对 VCE Production [949]／Client 100、分组和物料数。
3. 有问题点取消；确认无误才点**确认并开始**。
4. 如提示则完成 SAP 登录。当前任务运行或暂停时不要另开相同任务。
5. 观察 NPL 查询、Commodity 检查、Buyer Receipt 创建与保存绿色确认、RFQ 创建、结果保存等步骤。

![RFQ 正式系统确认](manual-assets/07-rfq-confirmation.png)

*图7 - 创建 RFQ 前的正式系统确认。*

![RFQ 进度](manual-assets/08-rfq-running.png)

*图8 - 模拟培训任务的 RFQ 状态区。*

进度按已处理**分组**计算，不是按物料行。一个组可包含多颗物料，已处理组也可能是跳过而非新建。预计剩余时间会随 SAP 响应变化，不是承诺的完成时间。

### 8.5 Commodity 和 Buyer Receipt 检查

创建 Buyer Receipt 前，系统会检查重新匹配的 NPL 数据中的 Commodity。如果出现**需要维护 Commodity**：

1. 阅读受影响物料号。
2. 当前可用时点**打开修正会话**，否则使用另一个已有 SAP 会话。
3. 在具备权限的独立会话维护正确 Commodity，保持暂停的 NPL 自动化页面不变。
4. 返回 Hub，点**已修复，重新检查**。
5. 等待验证；问题仍存在时，任务继续暂停。

额外会话可能因 SAP 上限或权限无法打开。这不代表可以随意切换原自动化窗口；请由 Key User 提供安全的修正途径。

![Commodity 暂停](manual-assets/09-action-required.png)

*图9 - Commodity 暂停及独立修正会话选项，使用培训数据。*

**NPL 数据读取失败**与主数据缺失不同：技术读取失败不证明 Commodity 为空。按提示点**重新读取并检查**，或请 Key User 检查当前页面和数据；不要只为了关闭报错就修改主数据。

SAP 已有有效 PPAP 日期时会保留。日期为空或过早时，系统可能使用 Excel 中的有效日期；仍不满足要求的行会记录待处理状态，不能当作完成。Buyer Receipt 必须通过保存及绿色状态检查后，RFQ 才继续。仅在软件明确提供并验证的恢复点，才按要求人工修正、保存当前 Buyer Receipt 后点 Continue；正常运行时不要人工 Save／Create。

### 8.6 查看 RFQ 编号与结果

1. 核对成功 RFQ、跳过、失败数量，不要把处理总数当成新建单据数。
2. 查看页面的**已创建 RFQ 编号**。
3. 点**打开结果文件**。原上传文件受到保护，状态写入工作结果副本。
4. 在副本中查看 **Buyer Receipt Status、RFQ Status、RFQ Number、Error Stage、Error Message**。同一成功分组的物料行写入同一 RFQ 号码。
5. 将业务结果另存到 Hub 临时／运行目录之外的批准位置。

*图10 - RFQ 结果按钮及虚构培训编号。*

如果 SAP 可能已创建 RFQ，但编号未确认，必须作为状态不确定处理。编号为空**不代表没有创建**；停止并核查 SAP 后再决定是否重试。

## 9. 批量维护供应商交货时间

打开**自动批量更新供应商交货时间（SLT）**。功能使用 WebGUI ME12，支持**标准采购（Standard）和寄售（Consignment）**信息记录。

### 9.1 模板与业务参数

使用 `ME12_Supplier_Lead_Time_Template.xlsx`，输入表为 **ME12 Upload**。A列填写 **Purchasing Info Rec.**，B列填 **Plant**。必要时以文本保留编号，避免丢失前导0；数字信息记录会规范为10位。

页面核对**工厂、采购组织、供应商交货时间（天）、采购类型**。默认 C100、C100、1天和标准采购。界面允许0-999的整数天数，请使用业务批准值。当前没有 Subcontracting／Pipeline 的可选项。

![SLT 业务选项](manual-assets/12-slt.png)

*图11 - SLT 准备、权限提醒及标准／寄售选择。*

### 9.2 执行步骤

1. 下载、填写并保存模板，再上传。
2. 查看选中信息记录数及抽样。只处理当前工厂；重复记录合并处理，结果回写对应原始行。
3. 选择标准或寄售，核对采购组织和天数。业务参数变化后会重新校验。
4. 点**开始自动化**，阅读**准备更新**后确认开始。
5. 在每个打开的浏览器完成证书选择及 SAP 登录。全部工作窗口准备好后才开始更新。
6. 不要操作运行中的浏览器。交货时间已符合要求的记录可以作为“无需修改”跳过。
7. 检查 **ME12 Status、Old Supplier Lead Time、ME12 Updated At**。

Key User 设置的是并发**上限**，小批量不一定打开全部窗口；实际数量还取决于待处理记录及浏览器资源。提高此值不会使 RFQ 或 Source List 并发。

Excel 可以保持打开。如果原文件被锁定，SLT 会在运行日志目录保存独立时间戳结果，不会强行覆盖打开的文件。请按**打开结果**返回的位置查看，不能假定原工作簿已包含所有结果。

记录无法验证时，不再安排新记录；已经处理中的记录可能先完成，保存部分结果后再显示只允许停止的暂停。重试前核查该信息记录在 SAP 中的真实状态。

## 11. 批量维护 Source List

打开**自动批量 Source List 维护**。Plant 固定 **C100**。系统新增或复用目标供应商行，**勾选 Fix，MRP 填1**，校验计划状态后保存。

> **警告 — 货源选择** — Fix／MRP 改变可能影响货源确定和计划。执行前请业务负责人确认目标供应商及是否双供。

### 11.1 模板及新增行参数

使用 `ME01_Source_List_Template.xlsx` 的 **ME01_Input**。

| 列 | 表头 | 输入／输出 |
| --- | --- | --- |
| A | Material No. | 必填物料。 |
| B | Parma | 必填目标供应商。 |
| C | Dual Sourcing | 必填明确 Yes／No；空白是错误，不默认为 No。 |
| D | ME01 Status | 程序写入，不作为输入填写。 |
| E | Error Message | 程序写入。 |
| F | Updated At | 程序写入。 |

页面新增行参数：**采购组织**默认 C100，**有效起始日期**默认页面初始化／重置时的本机当天，**有效截止日期**默认 2099-12-31。Hub 留开过夜后请重新核对起始日期；清空本页会恢复当前默认日期。新行日期直接按 SAP 的日-月-年格式写入，不会打开日历选择器。

### 11.2 Yes／No 的实际影响

| 模板选项 | 目标供应商行 | 其他全部供应商行 |
| --- | --- | --- |
| Yes | 新增／复用，Fix 勾选、MRP=1。 | 保留原 Fix、MRP、供应商、日期等，不修改。 |
| No | 新增／复用，Fix 勾选、MRP=1。 | 清空**全部**其他行的 Fix 和 MRP，包含历史／未来有效行；保留供应商、日期和其他数据。 |

No 不会删除旧供应商，只切换固定货源／MRP 标识。Yes 不代表自动新增一个与输入无关的第二供应商；你提供一个目标 Parma，其余已存在的行保留。SAP 本身的业务校验仍然生效。

存在唯一且覆盖本次有效期的目标行时，会复用以避免重复新增。如果多行都覆盖有效期，或目标行已有重叠但不同／较短的有效期，会暂停核查，不自动猜测、改写原日期或重复新增。

![Source List 双供预览](manual-assets/14-source-list.png)

*图13 - Source List 抽样中的 Supplier Parma 及明确的 Yes／No 培训选项。*

### 11.3 执行与验证

1. 每个有效行填写 Material、Parma、Yes／No，保存后上传。
2. 查看抽样及 No（切换固定货源）、Yes（保留其他 Fix）数量。
3. 核对有效期和组织。重复行必须具有相同供应商及双供选择，冲突会阻止执行。
4. 点**开始自动化**，阅读**准备更新**中对其他行的影响，再确认开始。
5. 按需登录并提供空闲会话。读取期间不要人工滚动或修改该 Source List。
6. 在结果文件查看 **ME01 Status、Error Message、Updated At**。同一工作簿已打开且可被正确检测时，结果通过 Excel 回写。
7. 用少量批准记录在 SAP 核对目标 Fix／MRP、其他行变化，以及供应商行和日期是否保留。

如果 SAP 已符合目标状态，会验证后跳过 Save。Excel 中旧的 SUCCESS 本身不构成依据，每次仍会核查 SAP。只读控件、不可读取行或回读不一致时安全停止；状态不确定时不会自动重复保存。

## 12. 通知、确认和状态

### 12.1 通知和声音

成功表示完成；提醒表示需要检查警告或用户处理；错误表示无法安全完成。包含跳过／问题的批次可以以提醒结束。可在设置关闭声音；声音失败不会改变任务状态或授权 SAP 操作。

请阅读消息和结果数量，不要只根据颜色或声音判断。

### 12.2 用户处理框中的按钮

Commodity 暂停示例见图9。先阅读具体问题和允许的按钮，再操作。

| 按钮 | 含义及操作要求 |
| --- | --- |
| Continue／继续 | 只在已支持恢复点提供。先修正问题，程序核查当前 SAP 状态后才继续。 |
| I've Fixed It - Recheck／已修复，重新检查 | 用于已确认的 Commodity 缺失。在独立会话修正后，让程序重新查询 NPL 并验证。 |
| Recheck NPL Data／重新读取并检查 | 数据读取失败时重新核对页面／数据，不代表已确认主数据缺失。 |
| Check Again／再次检查 | 重试当前可用状态检查，不是重放 Create／Save。 |
| Open Fix Session／打开修正会话 | 当前允许时打开独立修正会话，不会自动维护 Commodity，也不恢复原任务。 |
| Stop Automation／停止自动化 | 请求安全停止，保留已完成的修改／结果，不是回滚。 |
| View Details／查看详情 | 查看具体消息、Run ID、分组、Excel 行及恢复点，可提供给支持人员。 |

并不是每个暂停都有 Continue。写入结果未知或不确定时，可能**只有停止自动化**。Esc 不会关闭暂停。若要求填写字段，只提供所需业务信息，绝不填写 SAP 密码。

### 12.3 状态说明

任务页和历史页采用不同状态标签：

| 任务页标签 | 含义 | 应如何处理 |
| --- | --- | --- |
| Ready／等待上传 | 准备输入。 | 下载、填写、上传。 |
| Validating file…／正在校验文件… | 正在检查文件及参数。 | 等待。 |
| Ready to start／可以开始 | 有符合条件的数据。 | 核对后开始。 |
| Running／运行中 | 自动化正在执行。 | 不干扰运行中的 SAP 会话。 |
| Paused - waiting for you／已暂停，等待处理 | 需要指定用户处理。 | 按弹窗及允许按钮操作。 |
| Checking SAP…／正在验证 SAP… | 正在核查修正／状态。 | 等待，任务仍暂停。 |
| Completed／已完成 | 引导式任务已完成。 | 打开并保存结果。 |
| Completed with warnings／已完成，部分记录需检查 | 存在跳过或问题。 | 查看逐行结果。 |
| Could not complete／未能完成 | 未安全完成。 | 先查详情及 SAP 再重试。 |
| Stopped／已停止 | 已停止／取消。 | 查看部分结果。 |

RFQ 使用自己的进度文字，如查找 NPL 物料、创建 Buyer Receipt、创建 RFQ、执行结束。历史状态包括 **Running、Interrupted、Success、Partial、Failed、Cancelled**。Interrupted 需要核查；批次 Success 不证明每行都新建了单据。任务活动时顶部 Application status 保持 Running，暂停／验证状态优先显示。

## 13. 安全停止、重新检查与恢复核查

### 13.1 安全停止

1. 点顶部**安全停止**，或暂停框中的**停止自动化**。
2. 等待“正在安全停止…”及最终结果；不要重复点击或关闭 SAP 加速停止。
3. 打开部分结果，核对已保存内容后再准备重试。

> **重要 — 停止不是回滚** — 已保存 SAP 修改会保留。已停止任务仍可能创建过 Buyer Receipt／RFQ 或更新记录。

RFQ 尚未发出新 Create／Save 时，读取等待可以较快停止。操作已经发出后，系统可能先保护当前分组完成、捕获 RFQ 编号及 Excel 保存。正在执行的原生 SAP 调用必须先返回，不能由停止按钮强制中断。停止请求按安全边界生效后，不再有意开始下一个 RFQ 组。

SLT 工作窗口可能先完成当前记录；Source List 开始修改后会完成当前物料的校验／Save；APQP 等当前只读查询结束并保存结果。运行中关闭 Hub 也会请求同样的安全停止，可能需要时间。尽可能保持 Hub 和 SAP 打开，直到出现最终状态。

### 13.2 当前运行中的重新检查

受支持流程为**暂停 → 修正指定问题 → 重新检查 → 确认安全状态 → 继续**。Continue 不是忽略错误。无法证明状态正确时继续暂停，或只允许停止。可恢复暂停与已停止任务不是同一种情况。

第一个任务暂停时不要启动相同批次。消息消失、编号为空都不是直接重试依据；先对照已保存结果核查 SAP。

### 13.3 重启后的 Safe Recovery

之前 RFQ 未完成或状态不确定时，显示 **An unfinished RFQ run was found／发现未完成或状态不确定的 RFQ 运行**，包括项目、已处理组数、最后已确认检查点。例如7/12组、Buyer Receipt 已保存，不证明当前组 RFQ 未创建。

![Safe Recovery 人工核查](manual-assets/16-safe-recovery.png)

*图14 - 培训示例的7/12检查点；不是自动续跑。*

1. 确认旧任务／引擎已停止。旧引擎可能仍活动时，处理确认或结果打开可能被阻止。
2. 点**在 SAP 核查**，打开的是**人工检查清单**，不是自动 SAP 验证或维护。
3. 在对应环境的 SAP **显示模式**核对 Plant、Project、供应商、物料及已有 Buyer Receipt／RFQ；核查期间不要点 Create／Save。
4. 可用时点**打开结果**，与保存的 Excel 证据比较。它可能只反映最后一次成功 Excel 保存，而不是所有 SAP 提交。
5. 有疑问联系 Key User；确认后点**标记已处理**，阅读确认说明，再点**已核查，完成处理**。

没有强制书面备注或勾选表单。最终按钮表示你确认任务已停止且已查 SAP，系统记录时间和核查声明；它**不会**续跑、重放、回滚 SAP，也不会将任务改成 Success。

新 RFQ 在必需核查完成前不能开始；旧引擎活动也可能阻止其他任务。损坏／不可读的恢复证据不能按“无任务”忽略。不要删除隐藏恢复文件绕过保护。

## 14. 执行历史

进入**执行历史**查看本机任务，包含操作、开始时间、耗时、状态、结果、详情。可按功能／状态筛选并翻页，每页 **25条**。

![执行历史](manual-assets/11-history.png)

*图15 - 包含虚构培训记录的执行历史。*

点眼睛／详情按钮查看数量、SAP 事务、会话数、结果／备份／日志路径及恢复核查信息。当前历史页展示文件**路径**，不是统一的一键文件打开器。优先从任务页点打开结果／打开结果文件；按 Key User 指示，可将已确认路径复制到资源管理器。

### 14.1 一键清空日志

**一键清空日志 → 确认清空全部**，删除本用户符合条件的已结束历史和可识别诊断数据，范围是**所有页和所有筛选结果**，不是当前可见行。不可恢复，界面没有单条删除按钮。

此手动清理保留原上传文件、结果工作簿、备份和 SAP 数据。运行／未完成及未核查 RFQ 证据受保护；自动化运行中不能清理。不可读、被锁或无法安全删除的数据可能保留并显示警告。

被删历史不再用于任务排序、预计耗时学习和节省时间统计。收集支持证据前不要清理。

## 15. 结果、日志与本地数据

### 15.1 如何找到结果

使用任务的**打开结果**或 RFQ 的**打开结果文件**。查看详情会显示保存路径。无法打开时保留消息并联系 Key User，不要认为 SAP 没有修改。

| 功能 | 原文件与结果 | Excel 可否打开？ |
| --- | --- | --- |
| RFQ | 保留原上传文件；独立工作副本写状态／编号。 | 可以，但上传前要保存；原文件未保存的修改不是已上传输入。 |
| SLT | 通常更新输入文件；原文件被锁时另存时间戳结果。 | 可以；打开的原文件可能不含备用结果，请用打开结果。 |
| APQP | 通过 Excel 写 E列，查询前生成运行备份。 | 正确工作簿可安全连接时可以；只读／冲突副本需要处理。 |
| Source List | 写选定工作簿的结果列；检测到该工作簿已打开时通过 Excel 写入。 | 正确检测且可写时可以，保存失败必须核查。 |

### 15.2 查看诊断

普通用户优先查看任务详情和执行历史。Key User 要求日志时，进入**设置 → 高级／Key User 设置 → Diagnostics／诊断日志**。可搜索、按级别筛选、刷新、每页20条、打开日志目录，以及一键清空日志。

当前没有内置 Report Issue 上传器或自动生成支持包。通过日志目录获取 Key User 指定文件，只在批准的内部渠道共享。

### 15.3 保留期与隐私

历史、设置、浏览器配置、诊断、备份、工作结果保存在本机用户目录。V0.2.4 未新增云端遥测或自动日志上传。SAP／WebGUI 仍与公司系统通信，因此不能理解为“任何数据都不离开电脑”。

日志可能包含完整 Info Record、物料／供应商／项目／RFQ 编号、SAP 消息、数量及本机路径。向授权支持组之外共享前应检查／脱敏。隐藏文件夹不等于加密或安全保证。

自动清理在启动及每日空闲时执行。**60天**以前符合条件的已结束历史／日志和 Hub 管理的生成文件可能删除；未完成／未核查证据受保护，不清理运行存储之外的原始输入。

> **重要 — 单独保存业务记录** — 手动“一键清空”保留结果与备份，但独立的60天生成文件保留规则可能删除运行目录中的已结束工作副本／备份。及时另存重要结果到批准的业务位置，Hub 不是永久档案库。

## 18. 常见问题

**需要 Python 或 Node.js 吗？** 打包版不需要，保留完整解压目录即可。

**能从共享盘运行吗？** 推荐本机可写 C: 目录。受公司管理的网络位置可能导致阻止或启动变慢。

**Excel 可以保持打开吗？** 可以，但要遵守第15章各模块差异。SLT 被锁时可能返回独立结果。上传前保存，处理期间不修改输入。

**可以同时使用 SAP 吗？** 不使用自动化已占用会话。公司允许且未被 Hub 分配的独立会话才可使用；APQP 可能使用多个空闲会话，先核对实际数量。

**设置最大并发为什么没全开？** 设置是上限。SLT 还取决于记录数量与浏览器资源，APQP 使用已有合格空闲会话，RFQ／Source List 顺序执行。

**上传后为什么不能开始？** 等校验，查符合条件／无效数量和业务选项。其他活动任务或未完成 RFQ 核查也可阻止开始；文件修改后必须重新预览。

**为什么没有继续按钮？** 未知写入结果或不受支持页面刻意只允许停止，不是可以忽略错误。

**Cost Breakdown 的 No 为什么取消勾选？** 这就是当前规则。Yes 保留 SAP 原状态，No／空白取消。

**Source List 旧行的 Fix／MRP 为什么被清空？** 模板选了 Dual Sourcing No；旧供应商和日期仍保留。Yes 则保留其他行标识。

**RFQ 编号在哪？** RFQ 页面和工作结果副本的 RFQ Number 列。未确认编号时必须先查 SAP。

**标记已处理会重新执行 RFQ 吗？** 不会，只记录人工核查，不自动续跑或改成成功。

**能保证20秒，或视频里的速度吗？** 不能。SAP 延迟、分组大小、登录和保存确认都会影响时间。ETA／节省时间是估算；加速播放的视频不是实际耗时承诺。

**日志在哪里、可否删除？** 设置 → 高级／Key User 设置 → 诊断日志。“一键清空”作用于所有页符合条件的已结束历史／日志，保留活动和未核查证据。详见第14-15章。

| NO_MATCHING_RECORDS | 所选工厂无有效 SLT 记录。 | 核对工厂和输入。 |
| OPERATION_IN_PROGRESS | 其他任务／受保护操作活动。 | 安全结束或解决必需核查。 |
| ENGINE_UNAVAILABLE; EXECUTION_FAILED; BATCH_FAILED; UNKNOWN_ERROR | 引擎／批次未返回安全完成。 | 保留详情，核对 SAP 是否开始处理。 |
| BROWSER_LAUNCH_FAILED; INVALID_SAP_URL; NAVIGATION_TIMEOUT; NAVIGATION_FAILED | 浏览器／URL／网络失败。 | Key User／IT 查浏览器和访问。 |
| IPC_FORBIDDEN | 应用请求未获允许。 | 使用批准软件包，保留详情。 |
| CANCELLED; SAP_WAIT_BEFORE_WRITE | 任务取消，或新操作前停止读取等待。 | 检查部分结果，不是回滚。 |
| SIGN_IN | 登录／合格窗口检查需要用户处理。 | 按请求登录，再使用当前检查。 |
| COMMODITY_MISSING; NPL_READ_FAILED | Commodity 缺失或 NPL 无法读取，二者不同。 | 独立修正／重新检查，或技术排查。 |
| NPL_MATERIAL_RESET; NPL_MATERIAL_SCOPE; NPL_MULTI_MATERIAL; NPL_MATCH; NPL_REMATCH; NPL_REUSE | NPL 选择、范围、匹配／复用不能证明安全。 | 核对物料／项目和当前页，不盲重启。 |
| SAP_CONTROL; SAP_SELECTION; SAP_TIMEOUT; SAP_POPUP; SAP_SLOW_HARD_TIMEOUT | 控件、选择、响应或页面未确认。 | 按允许的暂停处理；未知写入结果先核查 SAP。 |
| CREATE_BUYER_RECEIPT; BUYER_RECEIPT_MATCH; BUYER_RECEIPT_SAVE; BUYER_RECEIPT_SAVE_CONFIRM; BUYER_RECEIPT_SAVE_POPUP | Buyer Receipt 创建、匹配或保存验证失败。 | 核查已有 Buyer Receipt 及受支持恢复点。 |
| BUYER_RECEIPT_SAVED_GREEN; PROD_RFQ_STAGING | 已识别人工恢复点，并不代表自动成功。 | 验证修正后的已保存绿色 BR／当前 RFQ 清单。 |
| PPAP_DATE_WRITE; PPAP_DATE_CONTINUE; INPUT_REQUIRED_PPAP_DATE | PPAP 日期更新／继续需要检查。 | 查批准日期和实际 SAP／单据状态。 |
| BUYER_RECEIPT_ERROR_RECOVERY; BUYER_RECEIPT_PREREQUISITE_CONTINUE; EXISTING_RFQ_CONTINUE | 前置条件／已有单据恢复未完成。 | 保留已有单据，查看当前页。 |
| PREFERRED_SUPPLIER_WARNING | 优选供应商问题需检查。 | 查业务主数据，不盲忽略。 |
| PROD_CREATE_RFQ_FROM_BR; PROD_CREATE_RFQ_FROM_BR_POPUP; PROD_RFQ_STAGING_TIMEOUT | 已保存 BR 到 RFQ 清单的转换未验证。 | 仅当前清单检查，不重复创建按钮。 |
| PROD_COST_BREAKDOWN; PROD_RFQ_BUTTON; PROD_RFQ_BUTTON_GUARD | 复选框更新或 RFQ 按钮未证明安全。 | 与 Key User 查供应商、可编辑性、页面。 |
| RFQ_GRID_MATCH; RFQ_INTERMEDIATE_MATCH | 物料不能唯一匹配。 | 不自动删／合并 SAP 行，先核查。 |
| RFQ_DUE_DATE; RFQ_EMAIL; RFQ_ATTACHMENT_UNSUPPORTED; RFQ_COMMENT_UNSUPPORTED | 抬头、日期、邮箱或不受支持的可选请求失败。 | 修正批准输入；普通模板未承诺附件／评论功能。 |
| RFQ_POPUP; RFQ_POPUP_LOOP; RFQ_POPUP_UNKNOWN; RFQ_POPUP_WAIT; STALE_POPUP | RFQ 确认／弹窗状态无法安全理解。 | 保留状态，停止核查，不盲点击。 |
| RFQ_NUMBER; CREATED_NUMBER_NOT_FOUND; POST_RFQ_RECOVERY | RFQ 可能存在，编号／返回状态不确定。 | 任何重试前先查 SAP。 |
| ALREADY_EXISTS; DUPLICATE_SKIPPED | 已有／完全重复的行跳过。 | 查看状态，不强制重复新建。 |
| ME12_RECORD_FAILED; UNVERIFIED_STATE | 某采购记录／查询不能安全完成。 | 停止、保留部分结果、验证真实记录。 |
| NO_RESULT; NO_DATE; DETAIL_POPUP | APQP 无可用结果／日期，或详情弹窗。 | 查看逐行日志，不编造日期。 |
| EXCEL_CONFLICT; WRITE_ERROR | APQP 输入／日期变化或回写失败。 | 保留文件／结果，由支持处理冲突。 |

Source List 行／控件／重叠／只读失败还使用具体阶段与说明文字，不为每种行错误单设代码。不要用编造的错误编号代替实际详情。
